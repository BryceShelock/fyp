# Backend Multi-Task Model Documentation (S1/S2/S3 + BERT Multi-Head + LoRA)

This document explains the backend model design for psychological modeling and risk detection, including weak-supervision labeling rules, training/evaluation workflow, and inference output format.

## 1. Task Definition (Three-Layer Task Design)

The model uses **multi-task learning** with one shared BERT encoder and three task-specific heads:

1. **Task 1: S1 (problem type, multi-label)**  
   - Type: multi-label  
   - Label set (8 trainable classes):
     - `academic`
     - `career`
     - `family`
     - `relationship`
     - `social`
     - `self`
     - `stress`
     - `other`

2. **Task 2: S2 (mental state, single-label)**  
   - Type: single-label  
   - Label set (current implementation, 3 classes):
     - `depression`
     - `anxiety`
     - `none`

3. **Task 3: S3 (risk detection, single-label)**  
   - Type: single-label  
   - Label set (current implementation, 3 classes):
     - `suicide_ideation`
     - `self_harm`
     - `none`

## 2. Final Label Structure (Model Output for UI)

The raw model output is:

```json
{
  "text": "...",
  "s1": [0,1,0,0,0,0,1,0],
  "s2": 1,
  "s3": 0
}
```

The frontend then maps it to display fields:

```json
{
  "问题类型": ["学业压力", "人际"],
  "心理状态": "焦虑",
  "风险等级": "中风险"
}
```

## 3. Automatic Labeling from Existing Data (Weak Supervision)

The current project mainly uses the existing Weibo sentiment dataset:
`dataset/weibo/微博评论情感数据集(清洗之后的，有标注，中文,csv格式)/clean_weibo_text.csv`

CSV format: `label,text`  
`label` follows the dataset README:
- `0`: joy
- `1`: anger
- `2`: disgust
- `3`: sadness

S1/S2/S3 labels are automatically generated by rules:

### 3.1 S2 Mapping (Weibo sentiment -> mental state)

Rule (`map_s2()`):
- if `label == 3` -> `depression`
- if `label == 1` -> `anxiety`
- otherwise -> `none`

### 3.2 S1 Mapping (keyword -> problem type, multi-label)

Rule (`map_s1(text)`, simplified but extensible):
- if text contains `作业` or `考试` -> `academic`
- if text contains `朋友` -> `social`
- if text contains `压力` -> `stress`

Other dimensions remain `0` unless triggered by their own keyword sets.

### 3.3 S3 Mapping (risk keywords -> risk class)

Rule (`map_s3(text)`):
- if text contains `不想活` -> `suicide_ideation`
- if text contains `割腕` -> `self_harm`
- otherwise -> `none`

## 4. Model Structure (One BERT + Three Heads)

Implementation file: `multitask_model.py`

Architecture:
- Backbone: `BERT`
- Heads:
  - `s1_head`: 8-dim logits (multi-label)
  - `s2_head`: 3-dim logits (single-label)
  - `s3_head`: 3-dim logits (single-label)

Loss:
- S1: `BCEWithLogitsLoss` (with `pos_weight` in training script)
- S2: `CrossEntropyLoss` (with class weights in training script)
- S3: `CrossEntropyLoss` (with class weights in training script)
- Weighted multi-task objective:
  - default: `s1=1.0`, `s2=2.0`, `s3=5.0`

## 5. LoRA Integration

Implementation file: `train_multitask_lora.py`

Current LoRA setup:
- `r=8`
- `lora_alpha=16`
- `target_modules=["query","value"]`
- `task_type=SEQ_CLS`

Trainable parameters are mainly LoRA adapters + classification heads (`s1_head/s2_head/s3_head`).

Dependency note: LoRA training requires `peft` (already included in `environment.yml`).

## 6. Key Backend-Related Files

- `multitask_config.py`: label definitions, weak-labeling rules, output formatting
- `multitask_model.py`: multi-head task model
- `train_multitask_lora.py`: training pipeline (CSV -> weak labels -> train/val/test -> save best)
- `multitask_predict.py`: inference script (text -> structured outputs)
- `backend_api.py`: FastAPI backend + SQLite persistence + WebSocket
- `gradio.py` / `app_gradio.py`: model UI and backend monitor tabs

## 7. Workflow (Training / Evaluation / Inference)

### 7.1 Before training

Install environment (recommended via `environment.yml`). Core dependencies include:
- `transformers`
- `datasets`
- `scikit-learn`
- `peft`
- `torch` (CUDA supported)

If your network is restricted, use offline/local package installation.

### 7.2 Smoke test (small sample first)

Run in project root:

```powershell
python .\train_multitask_lora.py --max_samples 200 --epochs 1 --batch_size 4 --max_length 32 --output_dir multitask_output_test
```

### 7.3 Full training + save best model

Example:

```powershell
python .\train_multitask_lora.py --device cuda --epochs 8 --batch_size 16 --max_length 128 --output_dir multitask_output_v3
```

Best model is saved under:
- `multitask_output_v3/best_model/`

### 7.4 Test-set evaluation

After training, the script prints test metrics based on `best_model`.

### 7.5 Single-text inference

```powershell
python .\multitask_predict.py --model_dir .\multitask_output_v3\best_model --text "我压力好大，作业又好多，朋友也不想理我"
```

The output is the same structured format used by the frontend.

### 7.6 Frontend demo (Gradio)

```powershell
python .\gradio.py
```

Enter text in the page to get structured prediction output.

## 8. Performance Metrics

Training/evaluation scripts compute metrics on `val/test` for all three tasks.

### 8.1 S1 (multi-label)

- `s1_subset_acc`
- `s1_precision_micro / s1_recall_micro`
- `s1_precision_macro / s1_recall_macro`

### 8.2 S2 (single-label)

- `s2_accuracy`
- `s2_precision_macro`
- `s2_recall_macro`

### 8.3 S3 (single-label)

- `s3_accuracy`
- `s3_precision_macro`
- `s3_recall_macro`

For risk modeling analysis, S3 macro precision/recall is usually the key focus because it better reflects class imbalance behavior.

## 9. Notes and Practical Considerations

Because S1/S3 currently rely heavily on weak supervision via keyword rules:
- training labels are inherently noisy;
- class distribution may be imbalanced;
- metric fluctuations are expected.

For thesis/defense wording, a practical contribution statement is:
**“multi-task joint modeling + upgraded risk detection design (S1-S2-S3)”**.
