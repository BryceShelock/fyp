# Backend Multi-Task Model (S1 / S2 / S3 + BERT Multi-Head + LoRA)

This document explains the **detection** backend: task definitions, weak-supervision labeling rules (see code for full keyword lists), training/evaluation workflow, and inference output. It does **not** replace the LLM “response” path (`chat_llm.py`, persona prompts in code).

## 1. Task Definition (Three-Layer Task Design)

The model uses **multi-task learning** with one shared BERT encoder and three task-specific heads:

1. **Task 1: S1 (problem type, multi-label)**  
   - Type: multi-label  
   - Label set (8 trainable classes):
     - `academic`
     - `career`
     - `family`
     - `relationship`
     - `social`
     - `self`
     - `stress`
     - `other`

2. **Task 2: S2 (mental state, single-label)**  
   - Type: single-label  
   - Label set (current implementation, 3 classes):
     - `depression`
     - `anxiety`
     - `none`

3. **Task 3: S3 (risk detection, single-label)**  
   - Type: single-label  
   - Label set (current implementation, 3 classes):
     - `suicide_ideation`
     - `self_harm`
     - `none`

## 2. Final Label Structure (Model Output for UI)

The raw model output is:

```json
{
  "text": "...",
  "s1": [0,1,0,0,0,0,1,0],
  "s2": 1,
  "s3": 0
}
```

The frontend maps it to display fields (example):

```json
{
  "问题类型": ["学业压力", "人际"],
  "心理状态": "焦虑",
  "风险等级": "中风险"
}
```

**Note:** At runtime, **`风险等级`** shown to the user may be driven by **`risk_scoring.compute_risk_score`** (using **S3 probabilities** plus optional text/history signals), not only the discrete S3 argmax. **`action`** (e.g. `ai_reply` vs `handoff_to_human`) comes from **`policy_engine.decide_policy`**. See `multitask_predict.py` and those modules for the exact pipeline.

## 3. Automatic Labeling from Existing Data (Weak Supervision)

The project can build training rows from the Weibo sentiment CSV:

`dataset/weibo/微博评论情感数据集(清洗之后的，有标注，中文,csv格式)/clean_weibo_text.csv`

CSV format: `label,text`  
`label` follows the dataset README:

- `0`: joy  
- `1`: anger  
- `2`: disgust  
- `3`: sadness  

S1/S2/S3 labels are generated by rules in **`multitask_config.map_s1` / `map_s2` / `map_s3`**. The code also matches a **whitespace-stripped** form of the text (e.g. `作 业` → `作业`) so keywords are not missed.

### 3.1 S2 Mapping (Weibo sentiment → mental state)

Rule (`map_s2()`):

- if `label == 3` (低落) → `depression`  
- if `label == 1` (愤怒) → `anxiety`  
- otherwise → `none`

### 3.2 S1 Mapping (keyword → problem type, multi-label)

Rule (`map_s1(text)`): **multiple independent keyword groups** per dimension (academic, career, family, relationship, social, self, stress, and a fallback `other` bucket).  

**Authoritative list:** see **`multitask_config.py`** — do not rely on abbreviated examples in old notes.

### 3.3 S3 Mapping (risk keywords → risk class)

Rule (`map_s3(text)`): e.g. phrases such as **不想活 / 活不下去 / 一了百了** → `suicide_ideation`; **割腕 / 自残 / 自杀 / 轻生** → `self_harm`; otherwise → `none`.  

**Authoritative list:** **`multitask_config.map_s3`**.

## 4. Model Structure (One BERT + Three Heads)

Implementation file: `multitask_model.py`

Architecture:

- Backbone: `BERT` (Chinese checkpoint chosen in training script)  
- Heads:
  - `s1_head`: 8-dim logits (multi-label)  
  - `s2_head`: 3-dim logits (single-label)  
  - `s3_head`: 3-dim logits (single-label)  

Loss:

- S1: `BCEWithLogitsLoss` (with `pos_weight` in training script)  
- S2: `CrossEntropyLoss` (with class weights in training script)  
- S3: `CrossEntropyLoss` (with class weights in training script)  
- Weighted multi-task objective (defaults in **`train_multitask_lora.py`**, e.g. `s1=1.0`, `s2=2.0`, `s3=5.0` — verify in script if you change them)

## 5. LoRA Integration

Implementation file: `train_multitask_lora.py`

Typical LoRA setup (see script for current flags):

- `r=8`  
- `lora_alpha=16`  
- `target_modules=["query","value"]`  
- `task_type=SEQ_CLS`  

Trainable parameters are mainly LoRA adapters + classification heads (`s1_head/s2_head/s3_head`).

Dependency note: LoRA training requires `peft` (see `environment.yml` / `requirements-pip.txt`).

## 6. Key Backend-Related Files

- `multitask_config.py`: label definitions, weak-labeling rules, output formatting  
- `multitask_model.py`: multi-head task model  
- `multitask_data.py`: CSV → tensors (Weibo weak labels or explicit multitask columns)  
- `train_multitask_lora.py`: training pipeline  
- `multitask_predict.py`: inference (library + CLI)  
- `risk_scoring.py`, `policy_engine.py`: risk score and routing  
- `backend_api.py`: FastAPI + persistence + WebSocket (calls predict + LLM for chat)  
- `gradio.py` / `app_gradio.py`: model UI and backend monitor tabs  

## 7. Workflow (Training / Evaluation / Inference)

### 7.1 Before training

Install environment (recommended via `environment.yml`). Core dependencies include:

- `transformers`  
- `datasets`  
- `scikit-learn`  
- `peft`  
- `torch` (CUDA supported)  

If your network is restricted, use offline/local package installation.

### 7.2 Smoke test (small sample first)

Run in project root:

```powershell
python .\train_multitask_lora.py --max_samples 200 --epochs 1 --batch_size 4 --max_length 32 --output_dir multitask_output_test
```

### 7.3 Full training + save best model

Example:

```powershell
python .\train_multitask_lora.py --device cuda --epochs 8 --batch_size 16 --max_length 128 --output_dir multitask_output_v3
```

Best model is saved under:

- `multitask_output_v3/best_model/`

### 7.4 Test-set evaluation

After training, the script prints test metrics based on `best_model`.

### 7.5 Single-text inference

```powershell
python .\multitask_predict.py --model_dir .\multitask_output_v3\best_model --text "我压力好大，作业又好多，朋友也不想理我"
```

The output is the structured format used by the backend / UI (plus internal fields such as `risk_score`, `action` when using `predict_text`).

### 7.6 Frontend demo (Gradio)

```powershell
python .\gradio.py
```

Enter text in the page to get structured prediction output.

## 8. Performance Metrics

Training/evaluation scripts compute metrics on `val/test` for all three tasks.

### 8.1 S1 (multi-label)

- `s1_subset_acc`  
- `s1_precision_micro / s1_recall_micro`  
- `s1_precision_macro / s1_recall_macro`  

### 8.2 S2 (single-label)

- `s2_accuracy`  
- `s2_precision_macro`  
- `s2_recall_macro`  

### 8.3 S3 (single-label)

- `s3_accuracy`  
- `s3_precision_macro`  
- `s3_recall_macro`  

For risk modeling analysis, **S3 macro precision/recall** is usually the key focus because it better reflects **class imbalance** behavior.

## 9. Notes and Practical Considerations

Because S1/S3 training labels are partly built from **weak supervision** (keyword / sentiment rules):

- labels are **noisy**;  
- class distribution may be **imbalanced**;  
- metric fluctuations are expected.  

For thesis/defense wording, a concise contribution line is:

**“Fine-grained multi-task detection (S1–S2–S3) plus a lightweight LLM-based response path, in a WeChat-style prototype.”**  
（细粒度多任务心理信号检测 + 轻量应答，在类微信插件原型中落地。）
